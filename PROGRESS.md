## Phase 1 — Build and design foundation (done)

**Goal:** a project that compiles, with every design token, string and build setting in place, so
later phases only add screens.

### Build configuration

- `gradle/libs.versions.toml` — full version catalog, grouped and commented.
- `build.gradle.kts` — added the google-services and Navigation SafeArgs plugins.
- `app/build.gradle.kts` — plugins applied, `viewBinding` and `buildConfig` enabled,
  Cloudinary values exposed as `buildConfigField`, all dependencies wired.
- `compileSdk` stays at **36**, as decided. `core-ktx` is pinned to 1.18.0 and `glide` to 5.0.7 —
  their newest releases declare `minCompileSdk=37`. Every other library is on its latest stable.
- Verified there is **no Kotlin plugin**: AGP 9.2.1 has built-in Kotlin support, confirmed by the
  presence of the `compileDebugKotlin` task with nothing applied.
- A missing Cloudinary property now fails at configuration time with a readable message instead of
  producing a confusing upload error at runtime.

### Resources

- `values/colors.xml` — the brand palette from SPEC §7, plus six light-theme neutrals the deck did
  not specify. Contrast was calculated, not guessed; see the report for the numbers.
- `values/dimens.xml` — spacing scale, radii, component sizes and the five text sizes.
- `values/styles.xml` — the five `TextAppearance.FitShare.*` styles and two shape appearances.
- `values/themes.xml` + `values-night/themes.xml` — Material3 DayNight, colour roles mapped in both
  themes, structure defined once in the light file.
- `font/font_heading.xml` (Rubik SemiBold) and `font/font_body.xml` (Heebo Regular + Medium).
  The three `.ttf` files were supplied by Roei.
- `values/strings.xml` — 123 Hebrew strings; `values-en/strings.xml` — the same 123 keys in
  English. Verified in sync, no drift, no duplicates.
- `xml/file_paths.xml` — FileProvider paths for the Phase 5 camera temp file.

### Code

- `FitShareApp.kt` — initialises the ServiceLocator and locks the app to Hebrew.
- `di/ServiceLocator.kt` — skeleton holding the application context and the shared
  `FirebaseAuth` / `FirebaseFirestore` instances. Repositories arrive in later phases.
- `AndroidManifest.xml` — permissions (`INTERNET`, `ACCESS_NETWORK_STATE`, optional `CAMERA`),
  the Application class, `supportsRtl`, `adjustResize`, and the FileProvider.

### Verified

`.\gradlew.bat assembleDebug` → **BUILD SUCCESSFUL**.

### Still open, deliberately

- `MainActivity` and `activity_main.xml` are still the Android Studio template. Phase 2 replaces
  them with the NavHost and the bottom navigation bar.
- **Dark is meant to be the default look** (SPEC §7). Right now the theme follows the system,
  because the default is set by `ThemePreferences`, which belongs to Phase 7.
- No screens, no data model, no repositories yet — all by design.

### Known limitations to carry into the README

- The Firestore rules cannot bound *how much* `likesCount` changes, only which fields change.
  Enforcing that needs Cloud Functions, which require the paid Blaze plan.
- `values-en/strings.xml` is never loaded at runtime; it exists to show that no text is hardcoded.
